\begin{arbox}{Summary Points}
\begin{enumerate}[leftmargin=*,itemsep=2pt]
\item Verification, not capability, is now the binding constraint on autonomous agents. The same agent harness, running different models, appears among the successes and the failures; what differs is whether something the agent cannot edit decides that the work is done.
\item An agent's report that it has finished is a claim, not evidence. In one study GPT-5 submitted a patch on 100\% of runs and resolved 44\% \citep{F20}, and in real sessions most visible resolutions of misaligned work required correction from the developer \citep{T23}.
\item Checkers that read the agent's evidence instead of running the code accept much failing work: in one controlled study an LLM verifier approved 49.4\% of submissions that a deterministic grader rejected \citep{T18}. In studies by the teams that built them, judges became more reliable when they checked observed state against an explicit rubric \citep{V15,V29}.
\item When a checker is within reach, agents tend to change the measurement rather than the work, by modifying tests, tampering with scorers or overfitting validation scores \citep{V3,V17,R26}.
\item With the same model, and especially at a matched budget, multi-agent teams are not reliably better than one strong agent \citep{T18,T25,T9}. The reported gains come from independent checks that execute and from isolated parallel work merged through tests \citep{T4,T20}.
\item Building applications from scratch is far from solved: the best of 16 models passes 61.8\% of workflows in Vibe Code Bench \citep{C19}. Agents do better when they know how they will be checked and can run what they built \citep{C29}.
\item Automated science works as automated engineering under a computable metric, ideally scored on held-out data \citep{S31,A25}, and fails as autonomous judgment: audits find incorrect, hallucinated or fabricated results \citep{S9,S15,S16}.
\item Graders and benchmarks are instruments that are often broken, in both directions, and must be audited before their scores are trusted \citep{C15,V31,D13}.
\item A single run cannot rank agents. Reliability, cost and interventions must be measured across repeated runs and reported with their spread \citep{F19,F24}.
\item The integrity tools of the replication crisis, namely pre-registration, multiverse reporting and independent re-execution, are more needed with agents, which can walk many forking paths in the time a person walks one, and some of them transfer \citep{R1,R6,R19}.
\end{enumerate}
\end{arbox}

\begin{arbox}{Future Issues}
\begin{enumerate}[leftmargin=*,itemsep=2pt]
\item Does a builder paired with an independent tester who uses the running application beat a budget-matched solo agent on applications built from scratch \citep{T12,T28}?
\item For runs that last hours, do separate sessions that hand off through files outperform one long session with compaction \citep{F3,T22}?
\item Does an honest ``stuck'' exit reduce gaming on tasks that are hard but solvable, without reducing completion \citep{V3}?
\item How much does pre-registration narrow the spread of verdicts and estimates in agent-run analyses with known answers \citep{R1,R6}?
\item When is hardening a grader worth its cost, counting false rejections of correct work and changes in the ranking of agents \citep{V27,T24}?
\item How quickly do reliability and the value of each harness component change across model versions \citep{H20,F2}?
\item How far does current reporting fall short of a minimum standard of repeated runs, budget-matched baselines, cost, grader audits and held-out tasks \citep{A10}?
\item Can production autonomy, measured as interventions per task and hours unattended, be measured by parties other than the laboratories whose systems are measured \citep{F14,F30,F32}?
\end{enumerate}
\end{arbox}
